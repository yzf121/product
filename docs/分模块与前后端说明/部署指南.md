## 3. 构建 MTA 包

### 3.1 构建命令

```bash
# 清理旧构建并构建 MTA 包
npm run build
```

**等效命令**：
```bash
rimraf resources mta_archives && mbt build --mtar archive
```

### 3.2 构建过程

构建过程包含以下步骤：

1. **清理旧文件**: 删除 `resources/` 和 `mta_archives/` 目录
2. **安装前端依赖**: `npm install`（在 `app/ai-chat-gui/` 下）
3. **构建前端**: `npm run build:cf`
4. **CDS 构建**: `npx cds build --production`
5. **打包 MTA**: 生成 `mta_archives/archive.mtar`

### 3.3 构建输出

```
mta_archives/
└── archive.mtar    # MTA 归档文件（用于部署）

gen/
├── srv/           # 后端服务构建产物
└── app/           # 前端构建产物
```

## 5. 配置服务

### 5.1 配置环境变量

部署后，需要在 BTP Cockpit 中为后端服务配置环境变量：

1. 打开 **BTP Cockpit** > **Cloud Foundry** > **Spaces** > 您的空间
2. 点击 `abap-clean-core-ai-fiori-new-srv` 应用
3. 进入 **环境变量/Environment Variables**
4. 添加以下用户定义变量：

**AI 对话必填**:
```
DASHSCOPE_API_KEY=sk-xxxxxxxxxxxxxxxx
DASHSCOPE_APP_ID=xxxxxxxx
```

**各 AI 助手应用 ID（可选，按需配置）**:
```
DASHSCOPE_APP_ID_ABAP=xxxxxxxx
DASHSCOPE_APP_ID_CPI=xxxxxxxx
DASHSCOPE_APP_ID_FUNC_DOC=xxxxxxxx
DASHSCOPE_APP_ID_TECH_DOC=xxxxxxxx
DASHSCOPE_APP_ID_CODE_REVIEW=xxxxxxxx
DASHSCOPE_APP_ID_UNIT_TEST=xxxxxxxx
DASHSCOPE_APP_ID_DIAGRAM=xxxxxxxx
```

> **注意**: 
> - `DASHSCOPE_API_KEY` 用于 AI 对话调用
> - 未配置的 AI 助手会回退到默认应用 ID

5. 点击 **Save**
6. **重启应用**：在应用概览页面点击 **Restart**

### 5.2 配置用户角色

1. 打开 **BTP Cockpit** > **Security** > **Role Collections**
2. 找到 `AIChat_User` 角色集合
3. 点击进入，添加需要访问应用的用户
4. 保存更改

### 5.3 Destination 配置（如需）

如果需要配置额外的 Destination：

1. 打开 **BTP Cockpit** > **Connectivity** > **Destinations**
2. 点击 **New Destination**
3. 配置如下：

| 属性 | 值 |
|-----|-----|
| Name | `dashscope-api` |
| Type | HTTP |
| URL | `https://dashscope.aliyuncs.com` |
| Authentication | NoAuthentication |
| ProxyType | Internet |

## 9. 常见问题

### Q1: 构建失败 - npm install 错误

**问题**: 前端构建时 `npm install` 失败

**解决方案**:
```bash
# 清理 node_modules 并重新安装
cd app/ai-chat-gui
rm -rf node_modules package-lock.json
npm install
cd ../..
npm run build
```

### Q2: 部署失败 - 服务创建错误

**问题**: 服务实例创建失败

**解决方案**:
1. 检查配额：确保有足够的服务配额
2. 检查权限：确保有创建服务的权限
3. 手动删除残留服务：
```bash
cf delete-service <service-name> -f
```

### Q3: 应用启动失败 - 端口绑定错误

**问题**: 应用启动时端口绑定失败

**解决方案**:
- Cloud Foundry 会自动分配端口，确保代码使用 `process.env.PORT`
- 检查 `package.json` 中的启动命令

### Q4: AI 功能不可用

**问题**: 部署后 AI 功能返回错误

**解决方案**:
1. 检查环境变量是否正确配置（`DASHSCOPE_API_KEY` 和 `DASHSCOPE_APP_ID`）
2. 确保已重启应用
3. 查看应用日志确认 API 密钥加载

```bash
cf logs abap-clean-core-ai-fiori-new-srv --recent | grep "\[AI\]"
```

**预期日志输出**:
```
[AI] 已配置的助手:
  - abap-clean-core: abc12345...
  - cpi: def67890...
```

### Q6: 用户无法访问应用

**问题**: 用户访问应用时提示未授权

**解决方案**:
1. 在 BTP Cockpit 中为用户分配 `AIChat_User` 角色集合
2. 等待几分钟让权限生效
3. 让用户刷新页面或重新登录

### Q7: 本地开发端口被占用

**问题**: 启动时提示端口已被占用

**解决方案**:
- 应用会自动尝试下一个可用端口（4005, 4006...）
- 或手动指定端口：
```bash
PORT=5000 npm run dev
```

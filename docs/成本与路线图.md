# 成本与路线图

> 更新日期：`2026-03-05`  
> 适用版本：`v1.4.3`

## 1. 成本结构（按当前实现）

项目当前成本主要来自三部分：

1. DashScope 大模型调用（主成本）
2. SAP BTP Cloud Foundry 运行资源
3. BTP 托管服务（XSUAA / Destination / HTML5 Repo）

由于附件解析已迁移到浏览器本地，当前实现不依赖后端文件上传/OSS 中转成本。

## 2. 成本影响因素

### 2.1 模型调用侧

- 请求量（用户数 × 每日请求次数）
- 平均输入/输出 token
- 是否命中 `sessionId`（可减少重复上下文 token）
- 使用的助手类型及提示词长度

### 2.2 平台侧

- `abap-clean-core-ai-fiori-new-srv` 实例规格与实例数
- 是否使用免费层（不同子账号/Region 策略不同）
- 日志保留策略与运维工具链

## 3. 估算方法（建议）

可用以下方式做内部预算：

```text
月模型成本 ≈ 日请求数 × 30 × (平均输入token单价 + 平均输出token单价)
月平台成本 ≈ CF 运行资源 + 托管服务费用
总成本 ≈ 月模型成本 + 月平台成本
```

建议按 3 个压力档进行压测后再定预算：

- 低负载：个人/小范围试点
- 中负载：团队级日常使用
- 高负载：多团队并发使用

## 4. 当前成本优化点

已落地：

- `sessionId` 优先策略（减少重复历史）
- 流式输出（改善体验，减少超长重试）
- 本地解析附件（避免后端文件链路成本）

可继续优化：

- 分助手设置更精细的系统提示词长度
- 记录 token 用量并按助手做月度报表
- 对超长上下文实施裁剪与摘要

## 5. 现状与已知限制

| 项目 | 当前状态 | 影响 |
| --- | --- | --- |
| 本地附件解析 | 已支持 txt/md/json/csv/xml/pdf/docx/xlsx/xls | 常见文档可用 |
| doc/ppt/pptx 解析 | 扩展名可选，但未实现解析链路 | 需先转 docx/pdf |
| 对话存储 | 浏览器 `localStorage` | 换设备不共享 |
| 代码组织 | `Main.controller.js` 体量大 | 维护成本偏高 |

## 6. 路线图（建议优先级）

### P0（近期）

- 完成 `doc/ppt/pptx` 浏览器解析能力，消除能力与 UI 提示偏差
- 增加 token 与错误码观测面板（按 aiType 统计）
- 拆分 `Main.controller.js`，降低维护风险

### P1（中期）

- 服务端会话/历史同步（替代纯本地存储）
- 企业权限域下的审计日志与留痕
- Prompt 模板管理（可配置、可版本化）

### P2（长期）

- 多模态输入（图片/截图）
- 可插拔助手能力（按团队扩展）
- 标准化 API 对外开放（鉴权+限流）

## 7. 维护建议

- 每月复盘：请求量、平均 token、失败率、峰值并发
- 每版本复盘：新增助手是否带来可量化收益
- 每季度复盘：BTP 规格是否与实际负载匹配

> 价格与计费规则请始终以阿里云与 SAP 官方控制台实时信息为准。
